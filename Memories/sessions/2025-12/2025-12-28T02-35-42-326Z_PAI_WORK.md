### Design Section 2: Adapter Logic & Configuration

The `pai-adapter.ts` (formerly `pai-core.ts`) is the bridge. It connects the static `PAI_DIR` content to the dynamic OpenCode runtime.

**1. Configuration (`settings.json`):**
We'll use a local JSON file to tell the adapter where "home" is.
```json
{
  "PAI_DIR": "/home/wallase16/Workspaces/pai-opencode",
  "identity": "default",
  "logLevel": "info"
}
```

**2. Adapter Logic (`pai-adapter.ts`):**
The plugin will perform three key actions at startup:
*   **Load Config:** Read `PAI_DIR` from `settings.json`.
*   **Inject Skills:** Programmatically register `PAI_DIR/Skills` so OpenCode sees them (e.g., via `~/.opencode/skill` management or runtime injection).
*   **Bridge Events:** Listen for `session.idle` (or similar events) to trigger PAI behaviors like the Voice/History loop.

**3. Setup Script (`setup-adapter.sh`):**
A robust script to automate the "wiring":
*   Prompts user for `PAI_DIR` location.
*   Generates `settings.json`.
*   Symlinks `opencode/plugin/pai-adapter.ts` to `~/.config/opencode/plugin/pai-adapter.ts`.
*   Verifies everything works.

**Does this logic flow (Config -> Adapter -> Runtime) look solid?**
A) Yes, that's the correct flow.
B) No, I want to stick to environment variables (`.env`) instead of `settings.json`.
C) I want the adapter to auto-discover the directory without config.
